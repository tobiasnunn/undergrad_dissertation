old parameters vs new parameters

When I used EggNOG-mapper last year, I copied the parameters from those used by the online version of EggNOG-mapper. I have since discovered, from the eggnog wiki, that I should not have run DIAMOND on complete genomes (which is what I was doing). I now have a separate step to convert genomic fastas to protein fastas, using prodigal.

Claude.ai recommended the following parameters, as “providing a good balance between accuracy and performance”:

--sensmode fast--pident 30--query_cover 50--evalue 1e-5

For comparison, my original parameters were:

--score 60

--pident 40

--query_cover 20

--subject_cover 20

--evalue 0.001

I have no idea what the significance of these parameters are. It is the type of thing one would need an expert to explain to them (or, at least, several years of experience), so I am going to trust that Claude.ai knows what it is talking about. Here is the wiki for DIAMOND:

I wanted to compare the outputs of the old and new parameters on 5 sample fastas. I intended to both search and annotation, in order to compare the two annotation files. However, search took so long with the old parameters that I instead decided to compare the 2 “hits” files, which are created at the end of the search phase. I also upped the memory usage from 8g to 32g.

OLD:

Total hits processed: 16168

NEW:

So, I actually got more hits using the new parameters (which I assume is good), in much less time than the old parameters. I did a comparison of the values for a random selection of contigs, and the values were the same in each file. I conclude that Claude.ai knows what is good, it takes far less time and requires far less memory.

Results

I feel I need to put this somewhere, might as well be here:

I split eggnogmapper into 3 pieces because it made the process go faster

This can be found on the github for EggNOG-mapper, I gave this info to Claude.ai and it helped explain this stuff to me.

The in-built process of converting genomic fastas to protein fastas in eggnog-mapper is much slower than using prodigal directly, I am not sure quite why.

To perform the search, DIAMOND is used, and there is a large amount of time for this to load and start searching. It is much more efficient to load it once and perform much bigger searches (i.e. on 1000 protein fastas at once).

To perform the annotation, the eggnog database (44 GB) is used. Even running on a high memory node on hawk, it takes a minimum of 60 seconds to load the eggnog database. It is therefore more efficient to load it once and perform much bigger annotations.

I ended off by simply gziping copies of all 4 annotation files, and manually dragging them into my onedrive using the mobaxterm interface, just for safe keeping.
