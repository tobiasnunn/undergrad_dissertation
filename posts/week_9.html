Smaller archive folders

I used the following to compress each one:

tar -cf - ./<folder name> | xz -9ve > <archive_name>.tar.xz

It is quite a slow process; a 5GB directly took 90 mins to compress to 4.2G - hardly worth it really.

Larger archive folder

Inside the archive folder I created today there are a lot of annotations folders from eggNOG-mapper. Each one isn’t huge but together they combine to nearly 9.5GB.

For these, I created separate folders so that folders with similar accession numbers (e.g. GCF_0001xxx or GCA_0001xxx) are grouped together in a folder with that prefix, using this script:

if [ -d "$dir" ]; then
digits=$(echo "$dir" | sed 's/GCA_\([0-9]\{4\}\).*/\1/')
prefix="GCA_$digits"
mkdir -p "$prefix"
mv "$dir" "$prefix/"
echo "Moved $dir to $prefix/"
fi
done

Then I compressed them in batches like this:

for dir in GCF_0011 GCF_0012 GCF_0013 GCF_0014 GCF_0015; do
[ -d "$dir" ] && tar -cf - "$dir" | xz -9ev > "${dir}.tar.xz" && echo "Compressed $dir"
done

Results

Descriptions of the 6 functions I made (not really results, but ideal for when it comes time for write up)

Utility Functions

  • “get_secrets” - reads in secrets file from my machine, uses an argument that decides what system the secrets are for. (i.e. “ncbi” or “SQL”, not real secrets, as the real names match to the secrets file)

  • “check_and_create_dir” - uses the base R function dir.create to create a directory

NCBI Functions

  • “get_taxID” - loads in the secrets file using “get_secrets” and a scientific name. There are two arguments to be passed in, “taxonomic_name” and “desired_rank”. For example, “Mustelidae” and “family”. I set a default value for “desired_rank” of “genus”, because that is the only level I will most likely be working at. Line 27 creates “encoded_taxon”, this is important for when the desired rank is species, as the binomial name has to be passed, but the call does not accept spaces, so the space must be encoded. The API call is called, using fairly standard code that can be found in the httr2 documentation, the returned values are then stored in a dataframe called “result”, which is returned at the end of the function. This object contains the taxonomic ID and the scientific name. This function uses purrr, a powerful package, and one I understand little. Claude.ai helped a lot with the creation of that as it had to be very clever. I think going forward I would like to do it the hard way of learning about how to do these things from online myself, however, I am on a bit of a time crunch, if I stopped everywhere, this would take a long time.

  • “download_taxonomic_information_by_tax_ID” - There are two arguments for this function, “tax_ID” and “file_location”. The first is very similar to the output of “get_taxID”, however, is a vector of multiple taxonomic IDs (i.e. the first column of “result”). The second is where the output file of this function should be stored. Firstly, the secrets are loaded, a check is also done to make sure “file_location” exists, if it does not the aforementioned “check_and_create_dir” function creates it. Early on, the vector of taxonomic IDs are transformed into a comma-separated string. This is then passed into another API call. Worryingly, about 50 lines of code exist in this function purely to flatten out the list object that comes back and turns it into a dataframe with all the relevant information inside. After all the fields I have to do different stuff to to keep are recombined, the object is saved out as an .rds file with a name of this format <file = paste0(file_location, “taxonomy_information_”, paste0(final_frame$organism_name, collapse = “”), ””, Sys.Date(), “.rds”)>, in the “01_inputs/03_metadata” section.

  • “download_accession_metadata_by_taxID” - This was originally inside the last function, but it just became too gargantuan. This is just for extra information, it uses another API call which gives information that could help contextualise the data at a later date. This one is simpler, it runs the call inside a for loop as this one can only take one taxonomic ID at a time, it then extracts and stores the result, saving it out as another .rds under <file = paste0(file_location, “accession_information_”, paste0(tax_ID, collapse = “”), ””, Sys.Date(), “.rds”)>

  • “get_dataset_by_accession” - There are two arguments to pass in. The first is “accession”, this is a vector extracted from the output of “download_taxonomic_information_by_tax_ID”. The second is “ftype”, this call is capable of returning genomic fastas and protein fastas (as well as other things that did not seem important enough to include). I set the default as “both” because I am not sure which I want yet. This one will be called on a file run on Hawk. The usual setup is done, as well as an extra bit. I decided that the best way to resolve the “both” or one or the other issue was to create a blank list with both fields, then use an if statement to remove one or the other if the ftype isnt both. A tempzip file is set up, this is a clean way of temporarily storing the output of the call and is then read in after. At the end of the file this then needs to be deleted. The call is run to get the fasta files. The output is modified until the desired information remains, then it is returned as a list where each item is the information for one accession. In the “04_fastafile_getter.R” script (from where it will be run), they are saved out as rds files. I will do this as 1 rds per genus.
